## kkFileView-dev：确认 base→final 级联已在远程生效

用户反馈 `git push origin master` 返回 "Everything up-to-date"，并要求确认远程 Action 是否会在 base 更新后自动重建 final 镜像。

### 诊断
- 初次 `git fetch` + `git log origin/master..HEAD` 显示本地领先 34 commit（远程 HEAD 显示为 `c4288f7e` 上游原始 commit）—— 与 push up-to-date 矛盾。
- 根因：**本地 `origin/master` 引用缓存陈旧**（fetch 执行了但未更新引用），不代表远程真实状态。
- `git ls-remote origin refs/heads/master` 直接查远程 → `355ec844`（= 本地 HEAD），证明用户**已成功 push**，远程已是最新代码。
- 本地 `git rev-parse origin/master` = `c4288f7e`（陈旧缓存）；`git branch -vv` 的 `ahead 34` 基于此缓存，不准。

### 结论
- 远程 `build-base.yml`（SHA `355ec844`）已含 `rebuild-final` job（第 69 行，`needs: build-base`），Round 15 改动已生效。
- 触发链：`building/base/**` 变更 / 每周一 03:00 UTC / `workflow_dispatch` → `build-base` 重建 `kkfileview-base:latest` → `rebuild-final`（needs build-base）`mvn package` + buildx 推送 `kkfileview:latest`（amd64+arm64，`--provenance=false`，inline cache）+ 冒烟测试。
- 满足约束：基于最新 base、不动版本号（只推 `:latest`，不推 `:VERSION`）、不发 Release、自动级联。

### 待办
- 本地 `origin/master` 引用陈旧是显示问题，不影响远程。如需本地引用同步，可 `git fetch origin --force` 或 `git remote update origin --prune`。
- base 更新后自动重建 final 的机制已就位，无需手动干预。

## Round 19：修正 Release Assets（只保留 jar + tar.gz）

用户截图显示 Release v5.0.2 Assets 只有 `images.txt` + Source code，缺少 jar/tar.gz。要求 Release 发布的必须是代码编译后的 jar 和代码打包文件。

### 根因
- `upload-artifact@v4` 默认保留相对目录结构：上传路径 `server/target/kkFileView-*.tar.gz` 下载后位于 `dist/server/target/kkFileView-*.tar.gz`。
- publish job 的 `softprops/action-gh-release` files 写的是 `dist/kkFileView-*.tar.gz` / `dist/kkFileView-*.jar`，glob 匹配不到嵌套路径下的文件，所以 jar/tar.gz 没上传。
- `images.txt` 是容器镜像 digest 文件，不是代码编译/打包产物，不应出现在 Assets 中。

### 实施（release.yml，commit f99e7079）
- release job 新增 step `Stage release artifacts`：创建扁平 `dist/` 目录，复制 `kkFileView-${VERSION}.jar` + `kkFileView-${VERSION}.tar.gz` + `images.txt` 进去。
- `upload-artifact` path 从多行 glob 改为 `dist/`，下载后文件直接位于 `dist/` 根目录。
- publish job 新增 step `Read image digests for release body`：读取 `dist/images.txt` 内容，通过 `GITHUB_OUTPUT` 注入 `body`。
- `softprops/action-gh-release`：
  - `files` 只保留 `dist/kkFileView-*.tar.gz` 和 `dist/kkFileView-*.jar`（代码产物）。
  - `body` 保留镜像地址文字，并把 `images.txt` 的多行 digest 内容直接嵌入 body（digest 不丢失，但不在 Assets 列表里）。
- 顶部注释第6条更新：images.txt 仅写入 Release body，不作为 Assets 附件。
- 校验：YAML OK；upload path=`dist/`；release files=`dist/kkFileView-*.tar.gz` + `dist/kkFileView-*.jar`；publish job 5 steps。
