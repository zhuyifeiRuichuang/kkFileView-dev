## kkFileView-dev：确认 base→final 级联已在远程生效

用户反馈 `git push origin master` 返回 "Everything up-to-date"，并要求确认远程 Action 是否会在 base 更新后自动重建 final 镜像。

### 诊断
- 初次 `git fetch` + `git log origin/master..HEAD` 显示本地领先 34 commit（远程 HEAD 显示为 `c4288f7e` 上游原始 commit）—— 与 push up-to-date 矛盾。
- 根因：**本地 `origin/master` 引用缓存陈旧**（fetch 执行了但未更新引用），不代表远程真实状态。
- `git ls-remote origin refs/heads/master` 直接查远程 → `355ec844`（= 本地 HEAD），证明用户**已成功 push**，远程已是最新代码。
- 本地 `git rev-parse origin/master` = `c4288f7e`（陈旧缓存）；`git branch -vv` 的 `ahead 34` 基于此缓存，不准。

### 结论
- 远程 `build-base.yml`（SHA `355ec844`）已含 `rebuild-final` job（第 69 行，`needs: build-base`），Round 15 改动已生效。
- 触发链：`building/base/**` 变更 / 每周一 03:00 UTC / `workflow_dispatch` → `build-base` 重建 `kkfileview-base:latest` → `rebuild-final`（needs build-base）`mvn package` + buildx 推送 `kkfileview:latest`（amd64+arm64，`--provenance=false`，inline cache）+ 冒烟测试。
- 满足约束：基于最新 base、不动版本号（只推 `:latest`，不推 `:VERSION`）、不发 Release、自动级联。

### 待办
- 本地 `origin/master` 引用陈旧是显示问题，不影响远程。如需本地引用同步，可 `git fetch origin --force` 或 `git remote update origin --prune`。
- base 更新后自动重建 final 的机制已就位，无需手动干预。
